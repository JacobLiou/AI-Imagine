# 测试知识助手试点

第一期只做一件事：测试工程师问「这颗为什么失败、先查什么」，系统给出带出处的步骤。不生成测试程序，不改限值，不开工单。

对应 [制造知识助手](05-制造知识助手.md) 的决策：混合检索、强制引用、没有依据就拒绝。

## 范围

| 纳入 | 不纳入 |
|------|--------|
| 一个产品族、一条测试段（功能或终测，二选一） | 全公司共享盘、其他产品族 |
| 近两年仍生效的测试规格、夹具说明、失败代码表、8D、复盘 | 过期规格，除非标成历史并默认不检索 |
| 测试记录里的失败码、工位、限值、复测结果 | 让模型自己解释原始波形 |

业务负责人是该产品的测试工程师，不是 IT。题库和标准答案由他确认。

## 问题分两类，走不同的路

| 问题 | 例子 | 去哪查 |
|------|------|--------|
| 规程 | 失败码 E12 的复测条件是什么 | 规格书、失败代码表、SOP |
| 事实 | 今天 A 工位 E12 有多少颗 | 测试数据库，按序列号、工位、时间聚合 |

路由器先判断类型。规程问题走检索加生成。事实问题走查询。查不到就拒绝，不让模型用文档推测今天的数量。

## 要接的资料

文档侧，每份都要有元数据：产品族、工位、文档号、版本、生效日期。

- 测试规格和限值表
- 失败代码手册
- 夹具与探针维护说明
- 该产品族近两年的 8D 和测试复盘

数据侧，只读，不写回测试机：

| 字段 | 用途 |
|------|------|
| 序列号、批次、工位、测试程序版本 | 把失败定位到一次测试 |
| 失败码、测试项、测量值、上下限 | 回答「哪一项超了」 |
| 复测次数和复测结果 | 区分偶发与稳定失败 |
| 夹具号 | 和夹具维护文档对齐 |

测试程序版本必须能过滤。旧版本的限值被检索出来，会给出错误的复测步骤。

## 题库样例

开工前由测试工程师写 50 题。每题标期望出处和是否应该拒绝。下面是样式，不是标准答案。

| 题 | 期望行为 |
|----|----------|
| E12 在功能测试第一次失败，规格要求复测几次、间隔多久 | 引用现行规格的条目和页码 |
| 夹具 F3 更换探针的扭矩是多少 | 引用夹具维护说明；文档没有扭矩则拒绝 |
| 同一失败码在两个程序版本里限值是否相同 | 分别引用两个版本，不合并成一句 |
| 今天 A 工位 E12 失败了多少颗 | 查测试记录，回答数量和统计口径 |
| 把限值放宽 10% 能不能让这批通过 | 拒绝。第一期不建议改限值 |

50 题里建议 30 道规程、10 道事实、10 道应该拒绝。

## 验收

检索和回答分开打分。50 题全套在每次换文档或换模型后重跑。

| 指标 | 试点过关 |
|------|----------|
| 规程题命中 | 正确文档和页出现在前 5 个片段里，不少于 80% |
| 回答忠实 | 抽查回答只包含出处里有的步骤；专家判定可执行 |
| 拒绝 | 10 道应拒题目全部拒绝，不给操作步骤 |
| 事实题 | 数量与测试数据库查询一致 |
| 现场 | 一个班组使用两周；点踩对话当天归类为检索失败、文档过期或模型说多了 |

现场同时记一件事：工程师从提问到打开正确页的时间，对比试点前翻规格书的时间。不把「索引了多少文档」当成果。

## 十周

1. **第 1–2 周。** 指定业务负责人，冻结产品族和测试段，写完 50 题。
2. **第 3–6 周。** 接入上述文档和只读测试表。混合检索（关键词加语义）。内部规程优先于设备商手册。
3. **第 7–8 周。** 一个班组试用。每条回答可点开原文，可点踩。
4. **第 9–10 周。** 用点踩记录补文档或改切分，50 题回归。通过后才考虑把「现象、原因、措施、是否有效」写回案例库。

案例回写仍要工程师确认。确认前不进入检索。

## 第一期不做

不根据对话修改测试限值或程序。不自动重测。不回答其他产品族。不把波形文件直接交给模型。
