# 视觉质检

对应 [AI 成功案例](../AI%20成功案例.md) 的路径一，以及博世类外观检测、富士康类电子外观、德州仪器 AM62A 参考设计。

这篇谈的是：相机看住一个工位，把「这件要不要拦截」变成可重复的判定。TI 的应用笔记 SPRADC9 把这条链路走完了一次：采集、标注、选 YOLOX-Nano、编译到 2 TOPS 加速器、跟踪坐标、看板上统计缺陷类型。实验室 50 件样品、10 圈重复为 100%，30 FPS 时加速器只占 22%、估算功耗 1.43 W。那是转盘模拟传送带，不是产线验收数字。

## 技术决策

先分清缺陷形态，再选模型族。三条路线不要混成一个「上 YOLO」：

| 现场条件 | 选型 | 原因 |
|----------|------|------|
| 缺陷类别清楚，有框或掩码标注，要给出位置和类型 | 监督检测，YOLO 一类单阶段检测器 | 要坐标才能分拣；类别要进质量看板 |
| 缺陷稀少、样子多变，只有大量合格图 | 无监督异常检测，如 PatchCore | 坏样本不够训练分类器；模型学的是「偏离正常」 |
| 光照稳定、缺陷是尺寸、缺口、有无 | 传统视觉：边缘、斑点、模板、测量 | 可解释、延迟低、换型成本小；深度学习解决不了标定问题 |

第二个决策是部署位置。节拍以帧计、图像不出厂时，模型放在工位工控机、Jetson 或 AM62A 这类边缘芯片上，导出 ONNX / OpenVINO / TensorRT。只有需要跨线对比、模型很大时才把图送到服务器。TI 这条参考设计选择边缘，是因为传送带等不了云端往返。

第三个决策是闭环深度。第一版做辅助：框出可疑区域，人确认。误杀成本高于漏检时，不要直接驱动剔除气缸。进入在线拦截之后，每次误判都要回到样本库，否则模型会停在上线那天的分布。

## 架构

```text
光电触发 → 相机（曝光/增益锁定）→ ISP / 去畸变
    → ROI
    → 检测器或异常模型
    → 跟踪（同一件跨帧只计一次）
    → 判定：放行 / 可疑 / 剔除
    → PLC 或分拣机构
    → 原图、框、判定、批次号落库，供复判和再训练
```

跟踪是产线架构里经常被漏掉的一层。检测器按帧输出框，计数和分拣要的是「一件产品」。SPRADC9 单独写了对象跟踪，把坐标交给分拣，并把缺陷类型送进看板。

训练侧和推理侧分开：

- 训练：标注规范、类别表、增强（亮度、小角度、尺度），固定验证集按工位而不是按随机图片切分。
- 导出：把框架模型编成目标芯片能跑的格式，在工位节拍下测延迟，而不是只看离线 mAP。
- 运行：阈值按「漏检成本 / 误杀成本」定，不按验证集最高 F1 直接搬到产线。

## 经典技术

- **单阶段检测**：YOLO 系列。骨干提取特征，颈部做多尺度融合，头同时回归框和类别。小缺陷常改损失函数（如归一化 Wasserstein 距离 NWD）和浅层特征，而不是换一个更大的骨干。
- **无监督异常检测**：PatchCore。用预训练 CNN（常见 Wide ResNet-50）抽出图像块特征，只存合格品的记忆库，用最近邻距离得到异常分数和热图。训练阶段不做反向传播。MVTec AD 是这个方向的公开基准：15 类物体和纹理、只含合格训练图、测试集含 73 种异常。
- **传统视觉**：阈值、连通域、模板匹配、卡尺测量。缺陷定义是几何量时，它仍是基线，用来证明「这个问题是否真的需要网络」。
- **部署**：ONNX 作为交换格式；NVIDIA 用 TensorRT；Intel CPU 用 OpenVINO；TI 用 Edge AI Studio 编译到 C7x/MMA。

## 参考范式

工业质检论文和开源项目反复出现的改法是：拿一个小 YOLO 当基线，只动骨干、颈部或损失，服务「低对比、小目标、要上边缘」。钢表面的 SDM-YOLO、AGE-YOLO，晶圆的 Wafer-YOLO，传送带橡胶的 CMT-YOLO，都是这条范式，不是另一套检测理论。

无监督范式的标准实验是：MVTec 某一类只喂合格图，报告图像级 AUROC 和像素级定位。Intel 的 Visual Quality Inspection 参考流程把这件事收成可配置的特征提取加 OpenVINO 推理。

和成功案例对齐的落地顺序仍是：缺陷定义清楚的一个工位 → 标注规范 → 辅助判定 → 再谈在线拦截。

## 交付示例：环形端子传送带工位

下面是一条假想但按 SPRADC9 条件写完整的工位。零件、四类缺陷和「边缘能跑小检测器」来自那份应用笔记；节拍、验收门槛和分期是示例里的项目决定，不是 TI 测出来的产线结果。

### 场景

连接器冲压之后，环形端子放在传送带上，姿态不固定。相机只看带上的一段。每分钟约 40 件，一件在视野里大约停留零点几秒。要认出四类并给出坐标，供后段拨杆分拣：

| 类别 | 含义 | 去向 |
|------|------|------|
| 合格 | 环和塑料都在 | 放行 |
| 半环 | 金属环不完整 | 缺陷箱 |
| 无塑料 | 缺绝缘 | 缺陷箱 |
| 无环 | 缺金属环 | 缺陷箱 |

漏到装配的坏件会造成退货；误剔的是一颗低值零件，可以人工回捡。所以漏检比误杀贵，但第一期仍不让模型直接驱动气缸。

### 技术决策

三条路线对一下这个工位：

| 路线 | 这个工位为什么不选或选它 |
|------|--------------------------|
| 传统视觉 | 不选。姿态不固定，「无塑料」是外观而不是一个卡尺尺寸 |
| PatchCore | 不作为上线模型。四类已经叫得出名字，分拣和看板要的是类别，不是一张热图。收数据的头两周可以拿它看「还有没有第五类」 |
| 监督检测 | 选。要框、要类别、要跟传送带同步 |

部署选工位边缘，不选云。40 件/分钟等不了上传，图像也不必出厂。训练在办公室的 GPU 工作站上做，工位只跑导出后的模型。

边缘硬件在两条里选一条，不要两套同时做：

| 方案 | 何时选 | 这个示例的选择 |
|------|--------|----------------|
| AM62A + Edge AI Studio，YOLOX-Nano 一类小模型 | 类别少、目标不算极小、功耗和成本敏感，而且已有同形态参考设计 | **选这条**。SPRADC9 就是环形端子，30 FPS 时加速器约占 22%，有余量 |
| 工控机或 Jetson + TensorRT，Ultralytics 的 nano 检测器 | 要更快迭代、缺陷后来变多、团队只熟 Python 训练链 | 作为退路。若 AM62A 上最小缺陷召回不够，再换，不在第一期并行 |

闭环分两期。第一期屏幕上画框，操作员按键确认，气缸不接。连续两周漏检和误杀都低于门槛后，高置信度才发给 PLC 剔除；置信度不够的滑到复判工位，不进自动拨杆。

### 选型结论

- 模型族：单阶段检测。基线用小模型（YOLOX-Nano 或同级 nano），先不要改骨干。
- 训练框架：工作站上用公开检测训练流程把数据和指标跑通。部署格式跟芯片走，TI 用 Edge AI Studio 编译，不把 PyTorch 原样放上板子。
- 运行时：相机进 GStreamer，片上推理，跟踪器把跨帧的框收成「一件」，看板按类计数。参考 [edgeai-gst-apps-defect-detection](https://github.com/TexasInstruments/edgeai-gst-apps-defect-detection)。
- 和控制的接口：工位 PLC 只收「放行 / 剔除 / 复判」和一件产品的触发，不收框坐标以外的调试信息。坐标留给工位程序自己算拨杆时刻。
- 许可证：若训练链用 Ultralytics，AGPL-3.0 要在项目开始时确认能不能进交付物。只交付编译后的 TI 模型、训练用自有脚本时，把这个风险圈在训练机上。

### 工位上有什么

```text
传送带
  → 漫射光源（频闪与曝光锁死，避免带速把零件拉糊）
  → 工业相机，视野只覆盖带的一段，分辨率先按「最小缺陷占 16 像素以上」反推
  → AM62A
        检测 → 跟踪 → 判定
        本地存原图、框、类别、置信度、时间、批次
  → 显示器：绿框合格，红框分缺陷类，旁边是当班计数
  → PLC：第一期只看信号灯；第二期收放行 / 剔除 / 复判
  → 复判台：低置信度零件停这里，人改标签，晚上回训练机
```

相机帧率按带速留余量。SPRADC9 的 30 FPS 是被相机卡住的，加速器没用满。这个工位先用 30 FPS 量产相机；若一件在视野里帧数少于 3，再换更快的相机，而不是先换大模型。

### 数据

上线前要有本工位的图，不能用应用笔记里的样品数字代替。

1. 光源、镜头、相机高度冻结之后再收。中途改曝光，旧标注作废。
2. 四类都要有。合格多取，三类缺陷每类先凑到能分开训练和验证，宁可用排产废品摆拍，也不要四类数量差出数量级后直接训练。
3. 标注规范写成一页：框贴外轮廓；半环和无环不要标成同一类；塑料反光仍标无塑料与否，不按反光标。
4. 验证集按班次和批次留，不从同一段视频里随机抽帧。同一件的连续帧只能全部在训练或全部在验证。
5. 每天把复判改过的标签增量进去。模型按周重训，不在工位上在线学。

### 验收门槛

这些是项目开工时写进合同的目标，用来决定能不能进入下一期。不是已经测到的结果。

| 阶段 | 过关条件 |
|------|----------|
| 实验室，冻结光学 | 四类在留出的批次上，缺陷召回达到约定值；误杀可放宽。报告按类列出，不报一个总准确率 |
| 影子模式两周 | 模型只显示、不剔除。和人工复判比漏检、误杀。光学漂移（脏镜头、换批次反光）单独计数 |
| 自动剔除 | 仅高置信度剔除。低置信度进复判。自动剔除造成的误杀有上限；漏检不低于影子模式 |
| 运行 | 工位掉线时传送带策略事先写好：停带，或整批改人工。不允许「模型没了就全部放行」 |

阈值用漏检和误杀定。验证集上 F1 最高的那个点只做参考。

### 交付物

| 交付 | 内容 |
|------|------|
| 光学冻结单 | 相机、镜头、光源、安装高度、曝光。改任何一项要重新抽样 |
| 标注规范 | 四类定义和正反例 |
| 模型包 | 编译后的检测模型、输入尺寸、类别表、置信度阈值 |
| 工位程序 | 采集、推理、跟踪、看板、本地存图 |
| PLC 点表 | 放行、剔除、复判、心跳。第二期才启用剔除 |
| 复判与重训说明 | 谁改标签、存在哪、多久训练一次、谁批准换上新模型 |
| 验收记录 | 按类的漏检和误杀，影子模式两周的班次 |

### 分期

1. **光学和基线（约 2–3 周）**：冻结成像，收一批四类图，在工作站上把小检测器跑通。不过线就改光，不改网络。
2. **边缘影子模式（约 2–4 周）**：编译到 AM62A，跟踪和看板接上，PLC 不动作。用真实班次对人工。
3. **有限自动（门槛达到之后）**：高置信度剔除，其余复判。心跳丢失则停带。
4. **稳定运行**：每周看复判比例。复判突然变多，先查光学和来料，再决定是否重训。

人员：一名视觉工程师负责数据和模型，一名控制工程师负责相机触发和 PLC，班组长负责复判口径。没有班组长认标注规范，后面的准确率没有意义。

### 这个示例里故意不做的

不在第一期上分类加分割两套模型。不上云端集中推理。不把拨杆闭环放进神经网络。不把 SPRADC9 的实验室 100% 写进验收报告。第五类缺陷出现时，先由人收进「其他」，积累够再加类重训，不在线改类别表。

## 不要照搬的地方

实验室 100% 来自固定样品、固定光照和已知四类缺陷。产线上要重新收图：反光、油污、姿态、相机脏污都会改变分布。有合格图但几乎没有坏样本时，先做 PatchCore 热图辅助复判；等坏样本积累够、类别稳定后，再训练检测器做分拣。
